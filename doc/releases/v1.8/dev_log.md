## 2026-07-23：D1 配置事务 Bugfix

### 根因

- 原实现直接修改正式内存配置，再直接覆盖正式 JSON 文件。
- 保存异常只输出到标准输出，调用方无法判断成功或失败。
- 设置窗口无论持久化是否成功都会发出成功信号并关闭。
- 开机自启注册表副作用与配置文件保存没有统一事务和回滚。

### 实现

- 新增可判断的 `ConfigSaveResult`。
- 新增候选配置副本，输入变化不再提前污染正式内存配置。
- 使用同目录 UTF-8 临时文件、刷新、`fsync` 和 `os.replace` 原子替换。
- 目录、临时写入或替换失败时保留原配置文件和正式内存配置。
- 开机自启变更失败时不落盘；落盘失败时恢复原注册表状态。
- 设置保存失败时显示明确反馈，保留窗口和输入，不发送成功信号。

### 测试先行证据

- 新测试首次运行因 `ConfigSaveResult` 尚不存在而按预期失败。
- 实现后配置与设置测试：`30 passed`。
- 配置、设置、v1.2、主流程和诊断定向回归：`88 passed, 1 skipped`。
- 受影响模块 ruff：通过。

## 2026-07-24：D4 1080p120 真实技术门禁

### 实现

- 新增独立真实捕获 spike、动态桌面刺激脚本和捕获门禁指标模块。
- 使用真实 dxcam / DXGI、项目 FFmpeg 8.0.1、`libx264 superfast` 和项目 FFprobe。
- 分离真实源更新与编码交付指标，避免 `video_mode` 重复帧被误判为真实 120 FPS。
- 补齐平均帧率、完整 1 秒最低帧率、backlog、输出解析、中文路径、取消清理、CPU 亲和性和异步编码管道测试。

### 定向优化

- 1440p 缩放链路最初只能达到约 80～87 FPS，正式门禁改为原生 1920×1080@120Hz 环境。
- BGRA 转 I420 后再写入 FFmpeg，降低原始管道带宽。
- 将采集与编码调度分配到不重叠 CPU 核心，并验证进程调度恢复。
- 尝试有界异步采集/编码管道、OpenCV 线程约束及 125 FPS 内部采样余量。
- 所有优化均保留原硬门禁，没有降低阈值或只以容器帧率判定通过。

### 结果

- 正式三次重复的真实源更新结果分别为：
  - `113.214 FPS / 最低 106`
  - `111.293 FPS / 最低 108`
  - `116.064 FPS / 最低 113`
- 三次仅一次通过，整体门禁未通过。
- 后续优化预检仍分别为 `113.383 FPS / 最低 107` 和 `113.093 FPS / 最低 109`，未形成稳定通过证据。
- 编码交付、FFmpeg 正常结束、1920×1080@120 输出解析、中文与空格路径及取消清理均通过。
- 自动测试 `17 passed`，D4 范围 ruff 与 mypy 通过。

### 决策

- 技术结论详见 `120fps-spike.md`。
- 依据 PRD 停止 D8、D9，不把 120 FPS 正式接入当前产品。
- D5-D7 工作台基础壳与视觉改版不依赖该门禁，继续实施。
