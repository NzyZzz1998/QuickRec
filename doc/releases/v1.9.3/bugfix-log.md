# QuickRec Full v1.9.3 缺陷记录

## BUG-193-001：静态桌面可能生成 0 帧录制

| 项目 | 内容 |
| --- | --- |
| 发现阶段 | D8 QuickRecCLI 真实录制 |
| 严重度 | 发布阻塞 |
| 当前状态 | 已修复，自动与冻结录制复验通过 |
| 影响范围 | 全屏录制；区域重建捕获链路复用同一首帧策略 |

### 复现

1. 保持桌面完全静止；
2. 使用源码 CLI 或既有 `hardware_smoke.py` 开始短时全屏录制；
3. DXCam 环形缓冲区在没有桌面变化时可能不提供初始帧；
4. 录制结束后编码器收到 0 帧。

### 根因

标准 30/60 FPS 捕获路径直接等待 DXCam 环形缓冲区，没有统一获取初始帧。
DXGI 在完全静止的桌面上可能没有可交付的新帧，因此录制循环无法建立首帧。

### 修复

- 所有 FPS 在开始时先尝试一次 DXCam `grab`；
- DXCam 暂时没有初始帧时，使用一次 Pillow `ImageGrab` 获取静态 BGR 首帧；
- 后续任何真实 DXCam 帧都会替换该静态兜底；
- 区域捕获重建后重新执行同一首帧策略；
- 不引入自绘光标，不改变编码目标 FPS。

### 验证

```text
ScreenCapturer 非硬件测试：20 passed, 8 deselected
受影响链路：231 passed, 8 deselected
冻结 CLI 静态桌面录制：92 帧，1920×1080，30 FPS，3.066667 秒
输出 SHA256：319F3D630B7562B400936BCC6550E18C05F9B4D06CF33CF77C13A40BEAC4F013
```

### 剩余说明

完全静止时，DXCam 自身的“桌面更新 FPS”可以为 0，但编码输出会按目标 FPS
复用首帧。这是采集更新指标与输出时间线指标的差异，不是 0 帧回归。

## BUG-193-002：删除片段后状态摘要残留已删除片段

| 项目 | 内容 |
| --- | --- |
| 发现阶段 | D10 RC1 GUI 验收 |
| 严重度 | 一般；不损坏项目数据，但会误导当前选择状态 |
| 当前状态 | 已修复，定向 UI 测试与 RC3 构建回归通过 |
| 影响范围 | 剪辑工作台命令提交后的片段选择和状态摘要 |

### 复现

1. 在剪辑工作台选中一个片段；
2. 执行“从时间线删除并波纹”；
3. 画布和片段检查器已经清除选择；
4. 状态摘要仍显示已删除片段的 `clip_id`。

RC1 证据：

```text
E:\QRtest\QuickRec-v1.9.3-acceptance\evidence\D10-editor-ripple-delete.jpg
```

### 根因

`TimelineEditorWindow._apply_command_result()` 在命令成功后无条件选择
`affected_clip_ids` 的第一项。删除命令的影响集合包含被删除片段，因此窗口状态
重新保存了一个已经不存在的 `clip_id`。随后 `_refresh_timeline()` 虽然清除了
画布选择，却没有同步重置文字摘要。

### 修复

- 命令提交后只保留仍存在于最新时间线模型中的片段 ID；
- 被选片段已不存在时，将窗口选择状态显式设为 `None`；
- 刷新时间线且没有有效选择时，将摘要统一重置为“未选择片段”；
- 不改变删除、全局波纹、撤销、重做或项目保存的数据规则。

### 验证

```text
定向 UI 测试：14 passed
全量非硬件回归：1031 passed, 29 deselected, 62 subtests passed
Packaging：17 passed, 1043 deselected
```

新增断言覆盖：

- 删除选中片段后 `selected_clip_id is None`；
- 状态摘要为“未选择片段”；
- 画布、检查器和命令状态保持一致。

该修复改变了生产代码，因此 RC1 不再是有效发布候选。RC2 曾为此重新打包，
随后又因 BUG-193-003 失效。

## BUG-193-003：分割后状态摘要仍显示分割前片段

| 项目 | 内容 |
| --- | --- |
| 发现阶段 | D10 RC2 GUI 验收 |
| 严重度 | 一般；时间线和项目文件正确，但界面会显示错误的当前选择 |
| 当前状态 | 已修复，定向 UI 测试与 RC3 GUI 复验通过 |
| 影响范围 | 分割、裁剪等命令提交后，仍然存在的选中片段及其状态摘要 |

### 复现

1. 在剪辑工作台选中一个片段；
2. 将播放头移动到片段内部；
3. 通过工具栏执行分割；
4. 时间线模型和画布已经生成左右两个片段；
5. 状态摘要仍显示分割前片段的 `clip_id` 和完整源范围。

### 根因

`TimelineEditorWindow._refresh_timeline()` 仅在当前选择为空时重置摘要。命令成功
后若仍存在有效选择，窗口会刷新画布，但不会依据最新时间线模型重新计算摘要
文字。因此分割后的新右片段已经被选中，摘要却保留分割前缓存。

### 修复

- 新增统一的 `_refresh_selection_summary()`；
- 片段选择和时间线刷新都通过同一入口读取最新模型；
- 有效选择重新计算 `clip_id`、源入点和源出点；
- 无效或已删除选择统一显示“未选择片段”；
- 不改变分割身份、保存事务、播放头或撤销重做规则。

### 验证

```text

全量非硬件回归：1031 passed, 29 deselected, 62 subtests passed
Packaging：17 passed, 1043 deselected
RC3 GUI：分割后立即选中新右片段，并显示源范围 00:01.866–00:03.066
```
