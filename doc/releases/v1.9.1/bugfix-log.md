## 2. BUG-191-01 单项首帧刷新状态未结束

- 严重度：一般。
- 复现：在项目素材详情点击“刷新首帧”，首帧已经生成成功，但页面状态仍显示正在刷新。
- 预期：任务进入成功、失败或取消终态后，页面应结束进行中提示并给出明确结果。
- 实际：生成成功后状态提示未闭合。
- 根因：页面只追踪批量重建任务，没有追踪单项刷新任务与终态之间的对应关系。
- 修复：
  - 增加单项刷新任务映射；
  - 成功、失败和取消后清理任务状态；
  - 分别显示“首帧预览已刷新”“刷新失败”或“刷新已取消”。
- 自动验证：
  - `test_refresh_preview_status_closes_after_task_finishes`
  - `test_refresh_preview_failure_keeps_retry_feedback_visible`
- GUI 复验：rc3 中已显示“首帧预览已刷新”，通过。

## 3. BUG-191-02 项目跳转素材库后目标被延迟查询覆盖

- 严重度：重要。
- 复现：素材库保留不匹配的关键词，随后从项目页点击“在素材库中查看”。
- 预期：清理旧查询条件，定位目标素材，并显示可返回原项目的上下文。
- 实际：目标素材短暂选中后，被 150 毫秒延迟查询再次隐藏，状态提示已定位但列表为
  `0 / N`。
- 根因：`focus_material()` 执行时，搜索输入框对应的延迟查询计时器仍处于等待状态。
- 修复：
  - 定位前停止待执行查询计时器；
  - 同步应用已重置的查询条件；
  - 再按稳定素材 ID 选择目标。
- 自动验证：
  - `test_material_library_focus_closes_pending_query_before_selecting`
- GUI 复验：rc3 中旧关键词被清理，目标素材保持选中，返回项目上下文正确，通过。

## 4. BUG-191-03 预览图覆盖素材操作按钮

- 严重度：重要。
- 复现：在工作台项目页选中已有首帧的素材，窗口高度接近默认或最小高度。
- 预期：预览图、详情和四个操作按钮边界清晰，按钮文字完整可辨且可点击。
- 实际：固定 `320×180` 预览与详情、两行按钮共同超过素材详情区可用高度，Qt 在无法满足
  最小尺寸时把按钮挤入预览图区域，导致按钮文字被画面遮挡。
- 根因：素材详情采用单一纵向布局，预览控件设置了过大的固定最小尺寸，操作区没有独立的
  可见性边界，也没有内部滚动降级。
- 修复：
  - 预览和素材元数据移入独立可滚动内容区；
  - 预览最小尺寸调整为 `240×135`，最大高度保持 `180`；
  - 四个操作按钮与重建进度移入固定、不透明的独立底栏；
  - 小窗口时只滚动预览和元数据，操作底栏始终可见且不与预览相交。
- 自动验证：
  - `test_material_actions_do_not_overlap_preview_at_minimum_workbench_size`
  - `tests/test_project_preview_ui.py`：10 passed
  - 全量测试：711 passed，1 skipped，26 deselected，52 subtests passed
  - 覆盖率：85.92%
  - ruff、项目配置 mypy、compileall、packaging 14 项通过
- 候选包：
  - rc3 已失效，不再作为最终验收对象；
  - rc4 EXE SHA256：
    `6D8A4DDE0FEC64E41637EE830B65EB795EAB9C041A719E081AE3D04055112B25`。
- GUI 复验：rc4 中预览区与固定操作区不再重叠，四个按钮均可辨认并可点击，通过。

## 5. BUG-191-04 中文空格路径无法在资源管理器中定位

- 严重度：发布阻塞。
- 发现阶段：rc4 候选包 GUI 验收。
- 复现条件：
  - 项目素材路径同时包含中文和空格；
  - 点击“打开目录”。
- 实际结果：
  - Windows 资源管理器打开“文档”，没有进入素材所在目录。
- 预期结果：
  - 打开素材所在目录，并尽量选中目标文件。
- 根因：
  - 资源管理器的 `/select,` 与目标路径被拼成单个子进程参数；
  - Windows 对含空格和中文的该参数解析失败后回退到“文档”。
- 最小修复：
  - 将 `/select,` 与完整文件路径作为两个独立参数传递；
  - 不使用命令字符串拼接。
- 回归要求：
  - 自动化测试固定参数边界；
  - 新候选包实际点击中文空格路径素材，确认资源管理器落点正确。
- 自动验证：
  - `test_open_folder_selects_unicode_path_with_separate_explorer_arguments` 通过；
  - 使用独立参数传递 `/select,` 和完整路径。
- GUI 复验：
  - rc5 实际打开
    `E:\QRtest\QuickRec-v1.9.1-acceptance\evidence\中文 空格\候选包样本.mp4`
    所在目录并选中目标文件；
  - 截图：
    `E:\QRtest\QuickRec-v1.9.1-acceptance\evidence\rc5-open-directory-unicode-space.jpg`；
  - rc6 相对 rc5 仅修改托盘退出顺序，文件操作证据可继承；
  - 结论：已关闭。

## 6. BUG-191-05 托盘退出后进程残留

- 严重度：发布阻塞。
- 发现阶段：rc5 候选包退出清理验收。
- 实际结果：
  - 日志记录“QuickRec 已退出”；
  - 工作台和托盘图标消失；
  - `QuickRec.exe` 进程仍驻留，FFmpeg/FFprobe 无残留。
- 预期结果：
  - 托盘“退出 QuickRec”完成后应用进程和媒体工具进程全部结束。
- 根因：
  - 托盘线程停止通过 `QTimer.singleShot(0, ...)` 延后执行；
  - 退出回调已经请求 Qt 事件循环结束，定时器没有机会运行；
  - pystray 非守护线程继续存活，阻止进程退出。
- 最小修复：
  - 退出回调返回后同步停止 pystray 图标线程；
  - 再调用 `QApplication.quit()`，不再依赖退出中的 Qt 定时器。
- 回归要求：
  - 单元测试固定“业务退出回调 -> 停止托盘线程 -> 退出 Qt”的顺序；
  - 新候选包从真实托盘退出后确认无 QuickRec、FFmpeg 或 FFprobe 残留。
- 自动验证：
  - `test_exit_stops_pystray_before_quitting_qapplication` 通过；
  - 托盘与主流程定向测试 51 项通过；
  - 项目标准测试门禁 714 项通过。
- GUI 复验：
  - rc6 从真实系统托盘打开工作台；
  - 从真实托盘菜单执行“退出 QuickRec”；
  - `QuickRec.exe`、`ffmpeg.exe`、`ffprobe.exe` 均在检查时不存在；
  - 启动 rc6 的验收进程自然返回退出码 0；
  - 日志在 2026-07-27 19:40:16 记录协调器停止和 QuickRec 退出；
  - 结论：已关闭。
